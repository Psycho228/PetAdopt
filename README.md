## 📱 О проекте

PetAdopt — это современное Android-приложение, которое связывает питомцев из приютов с заботливыми хозяевами. Приложение использует знакомый свайп-интерфейс (как в Tinder) для удобного поиска питомца и подробный опросник для оценки готовности пользователя стать ответственным хозяином.

### ✨ Ключевые возможности

- 🔥 **Свайп-механика** — листайте карточки питомцев, лайкайте тех, кто пришёлся по душе
- 💖 **Совпадения** — список лайкнутых питомцев с возможностью удаления лайков
- 📝 **Умный опросник** — 7 разделов, 40+ вопросов с современными UI-компонентами (выпадающие списки, чекбоксы, анимации)
- 📬 **Заявки на пристройство** — отправляйте заявки и отслеживайте их статус
- 🏢 **Кабинет приюта** — статистика, управление питомцами, просмотр заявок
- 🎯 **Управление заявками** — детальный просмотр заявок с опросником и оценкой рисков, подтверждение/отклонение
- 💬 **Чат с приютом** — обмен сообщениями в контексте заявки (Android + веб-панель)
- 👤 **Личный кабинет** — история заявок, ответы на опросник, настройки профиля
- 🔐 **Безопасная аутентификация** — вход через Supabase Auth (email/пароль или анонимно)
- 🌐 **Облачные данные** — синхронизация через Supabase в реальном времени
- 🤖 **Оценка рисков** — интеграция с GigaChat для анализа готовности пользователя
- 🖥️ **Веб-панель приюта** — React + TypeScript + Vite приложение для управления питомцами и заявками
- 📸 **S3 хранилище** — загрузка фото питомцев с SigV4 подписью (reg.ru Cloud)

## 🏗 Архитектура проекта

Проект построен по принципам **Clean Architecture** с разделением на слои:

```
app/src/main/java/com/example/petadopt/
├── data/
│   ├── model/             # Модели данных (User, Pet, Application...)
│   └── repository/         # Репозитории (Supabase/S3 реализация)
├── domain/
│   ├── model/              # Доменные модели
│   └── usecase/           # Бизнес-логика (UseCase'и)
├── di/                    # Модули внедрения зависимостей (Hilt)
├── navigation/            # NavGraph и routes
├── ui/
│   ├── components/         # Переиспользуемые UI компоненты
│   ├── screens/           # Экраны приложения
│   └── theme/             # Цвета, типографика, темы
├── viewmodel/             # ViewModels для каждого экрана
└── util/                  # Утилиты (S3, Supabase конфигурация)
```

## 📲 Установка и запуск

### Предварительные требования
- Android Studio Hedgehog (2023.1.1) или новее
- JDK 17
- Android SDK 34
- Настроенный Supabase проект
- **Файл `.env`** с API-ключами (см. ниже)

### Быстрый старт

```powershell
# Клонировать репозиторий
git clone https://github.com/Psycho228/PetAdopt.git
cd PetAdopt

# Создать файл .env из шаблона
cp .env.example .env

# Заполнить .env своими ключами (S3, GigaChat, Supabase)

# Собрать debug-версию
.\gradlew assembleDebug

# Запустить тесты
.\gradlew testDebugUnitTest

# Очистка и пересборка
.\gradlew clean assembleDebug
```

> ⚠️ **Важно:** Перед первым запуском создайте Supabase проект, настройте таблицы (см. [supabase-schema.sql](supabase-schema.sql)) и заполните файл `.env`. Без ключей сборка покажет предупреждение, но продолжится.

### Настройка Supabase
1. Создайте проект на [supabase.com](https://supabase.com)
2. Выполните SQL-скрипты из корня проекта:
   - `supabase-schema.sql` — создание таблиц
   - `add-role-column.sql` — добавление роли пользователя
   - `add_size_column.sql` — добавление размера питомца
   - `add_traits_column.sql` — добавление характеристик
   - `add_phone_email_columns.sql` — добавление контактов
   - `add_processing_status.sql` — добавление статуса обработки
   - `create_risk_assessments_table.sql` — таблица оценок рисков
   - `add_applications_indexes.sql` — индексы для производительности
   - `create_chat_messages_table.sql` — таблица сообщений чата
   - `add_chat_status_column.sql` — статус сообщения в чате
   - `add_contact_days_column.sql` — дни для связи в заявках
3. Настройте RLS политики (см. `pets_rls_policy.sql`, `fix_pets_rls.sql`)
4. Скопируйте `SUPABASE_URL` и `SUPABASE_ANON_KEY` в `.env`

## ☁️ S3 хранилище (reg.ru Cloud)

Приложение использует **S3 совместимое хранилище** для загрузки фотографий питомцев:

- **Провайдер**: reg.ru Cloud Object Storage
- **Бакет**: `pet-photos`
- **Доступ**: Path-style URL (`https://s3.regru.cloud/pet-photos/{key}`)
- **Авторизация**: AWS SigV4 подпись запросов

### Настройка S3
1. Создайте бакет `pet-photos` в reg.ru Cloud
2. Настройте публичный доступ на чтение (`s3:GetObject`)
3. Создайте Access Key с правами `s3:PutObject`, `s3:DeleteObject`
4. Добавьте ключи в `.env` файл:
   ```env
   S3_ACCESS_KEY=your_access_key
   S3_SECRET_KEY=your_secret_key
   S3_BUCKET_NAME=pet-photos
   S3_ENDPOINT_URL=https://s3.regru.cloud
   ```

### Известные проблемы и решения
- **Ошибка 403 Forbidden** — проверьте права Access Key и политику бакета
- **Ошибка RequestTimeTooSkewed** — время на устройстве должно быть синхронизировано (используется UTC)
- **Дублирование фото на UI** — исправлено: `selectedImages` очищается после загрузки

## 📊 Структура данных (Supabase)

### Таблицы
| Таблица | Описание |
|---------|----------|
| `users` | Профили пользователей (id, email, name, role, phone) |
| `pets` | Данные питомцев (name, age, type, gender, size, breed, photo_url, ...) |
| `applications` | Заявки на пристройство (user_id, pet_id, status, message, contact_days) |
| `questionnaire_answers` | Ответы на опросник (user_id + все поля анкеты) |
| `likes` | Лайки пользователей (user_id, pet_id, created_at) |
| `risk_assessments` | Оценки рисков от GigaChat (user_id, application_id, assessment_data) |
| `chat_messages` | Сообщения чата (application_id, sender_id, sender_role, message, status) |

### Статусы заявок
- `pending` — заявка на рассмотрении
- `processing` — заявка в работе (автоматически при открытии списка)
- `approved` — заявка одобрена
- `rejected` — заявка отклонена

### Роли пользователей
- `user` — обычный пользователь
- `admin` — администратор приюта (управляет всеми питомцами)
- `shelter` — сотрудник приюта (управляет своими питомцами)

## 📝 Опросник потенциального хозяина

**7 разделов, 40+ вопросов** для оценки готовности:

1. **Основная информация** (6 вопросов) — имя, возраст, город, работа, контакты
2. **Жилищные условия** (11 вопросов) — тип жилья, разрешение на животных, состав семьи
3. **Опыт с животными** (6 вопросов) — прошлые питомцы, опыт с собаками/кошками
4. **Ответственность и готовность** (10 вопросов) — понимание затрат, времени, рисков
5. **Безопасность** (4 вопроса) — сетки на окнах, стерилизация, адресник
6. **Эмоциональная часть** (3 вопроса) — мотивация, видение жизни с питомцем
7. **Желаемые виды животных** (1 вопрос) — какие питомцы вас интересуют

## 🤖 GigaChat интеграция

Для оценки рисков при подаче заявок используется **GigaChat** от Сбера:

- **Интеграция**: Ktor Client 2.3.10
- **Функция**: Анализ ответов на опросник и формирование оценки рисков
- **Результат**: `RiskAssessmentRecord` с рекомендациями для приюта

### Настройка GigaChat
```env
GIGACHAT_CLIENT_ID=your_client_id
GIGACHAT_SCOPE=GIGACHAT_API_PERS
GIGACHAT_AUTH_KEY=your_auth_key
```

> ⚠️ **Важно:** Ключи загружаются из `.env`. Для production-версии рекомендуется перенести работу с GigaChat на backend-сервер.
